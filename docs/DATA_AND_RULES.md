# 2025 선수 데이터와 게임 규칙

기준: **2025 KBO 정규시즌**. 다른 시즌, 포스트시즌, 퓨처스 기록은 섞지 않습니다.

## 명단과 공식 검증

- 10구단 × 타석 수 상위 15명 = 150명. 동률이면 KBO 선수 ID 순입니다.
- 원자료: KBO [기본기록 1](https://www.koreabaseball.com/Record/Player/HitterBasic/Basic1.aspx), [전체 기본기록](https://www.koreabaseball.com/Record/Player/HitterBasic/BasicOld.aspx).
- 각 페이지에서 시즌 2025, KBO 정규시즌(0), 해당 구단, 타석 내림차순을 지정했습니다. URL만으로 필터가 유지되지 않으므로 공식 페이지에서는 같은 필터를 선택해야 합니다.
- 시즌 중 이적 선수의 구단은 해당 시즌 공식 표의 구단 귀속을 따릅니다. 기록은 그 선수의 **시즌 합계**이며 구단별 이적 전후 기록으로 분할하지 않습니다. 현재 소속과 다를 수 있습니다.
- `data/sources/`의 두 종류 HTML 스냅샷, `manifest.json`의 필터·수집시각·SHA-256, `data/roster-2025.js`의 원기록을 보관합니다. 사이트 빌드에는 원본 HTML을 넣지 않습니다.
- 두 표의 공통 집계 일치, 시즌/구단 필터, 고유 선수 ID, 정확히 구단별 15명, 안타 구성 및 비음수 집계를 검증합니다.
- 타석과 `타수+볼넷+사구+희생번트+희생플라이` 사이에 잔여 타석이 존재할 수 있습니다. 이를 오류로 고치거나 다른 시즌 값으로 메우지 않습니다.
- 카드의 공식 출처 링크는 선수 연도별 기록 페이지이며 **2025 행**을 확인해야 합니다. 재현의 기준은 보관한 2025 구단별 표입니다.

```sh
node scripts/fetch-kbo.mjs        # 공식 사이트 네트워크 접근 필요
node scripts/import-kbo.mjs       # 스냅샷 검증 후 데이터 생성
node scripts/import-kbo.mjs --check # 변경 없이 원본과 생성물·해시 대조
```

수집 스크립트의 첫 구단 선택을 한 번 반복하는 것은 시즌을 바꿀 때 KBO 페이지가 구단 필터를 초기화하기 때문입니다. 가져오기에 실패하거나 필터가 맞지 않으면 생성 검증이 중단됩니다. 임의 수치로 대체하지 않습니다.

## 확률 변환 v1

선수별 `PA`를 분모로 아래 여섯 결과의 원시 빈도를 구합니다.

| 결과 | 원시 횟수 |
|---|---|
| 아웃 범주 | PA − H − BB − HBP |
| 볼넷·사구 | BB + HBP |
| 단타 | H − 2B − 3B − HR |
| 2루타 / 3루타 / 홈런 | 2B / 3B / HR |

게임의 아웃 범주는 희생타와 기타 잔여 타석도 포함하는 단순화입니다. 실제 공식 아웃 개수와 같다는 뜻이 아닙니다. 사구는 볼넷과 같은 밀어내기로 처리합니다.

소표본 극단치를 줄이기 위해 모든 선수에게 동일하게 가상 60타석의 **게임용 사전 분포** `[.64,.10,.18,.05,.005,.025]`를 더합니다. 이 분포는 타 시즌 기록이 아닙니다.

`보정 빈도 = (해당 결과 횟수 + 60 × 사전 분포) / (PA + 60)`

공격 중심 게임을 위해 아웃 외 다섯 확률에 1.45를 곱하고, 합계가 92%를 초과하면 같은 비율로 줄입니다. 아웃은 나머지입니다. 이는 **게임 확률**이며 실전 예측 모델이 아닙니다. 수치는 `rules.js`에서 한 번에 바꿉니다.

시너지·조건부 능력은 아웃 확률에서 해당 결과로 확률을 옮깁니다. 아웃 0% 아래로 내리지 않습니다. 구단 효과 '홈런 공장'만 단타 5%p를 홈런으로 옮깁니다. 카드에는 기본 게임 확률, 공격 화면에는 현재 적용 확률을 표시하며 표시 반올림 때문에 합계가 약간 다르게 보일 수 있습니다.

## 타격 유형과 창작 능력

분류 우선순위는 모두 2025년 기록만 사용합니다.

1. SB/PA ≥ 3.5%: 주루형
2. HR/PA ≥ 3%: 거포형
3. (BB+HBP)/PA ≥ 11.5%: 출루형
4. 나머지: 교타형

공통 능력 6종: 출루의 시작, 연결 고리, 주자 청소, 내야 흔들기, 하위 타선의 힘, 끝까지 승부. PA<200이면 하위 능력, 나머지에서 BB/PA≥14%이면 끈기 능력, 그 밖에는 유형별 능력을 부여합니다. 소표본 선수도 하위 타선 전략에 쓸 수 있도록 한 게임 설계입니다.

고유 능력 4종: 디아즈(빅 스윙), 박해민(그린 라이트), 최형우(승부의 중심), 송성문(끊기지 않는 흐름). 고유 능력은 공통 능력을 대체합니다. **모든 능력은 창작 효과**이며 실제 선수의 성격·특수능력에 대한 사실 주장이 아닙니다. 카드에 이를 명시합니다.

## 세 종류의 시너지

- 구단: 같은 구단 선발 3/5/7명에서 해당 구단 타자에게 지정 결과 +4/7/10%p. 높은 단계로 대체하며 중복 합산하지 않습니다. 연결·출루·장타·한 방 4종의 임시 효과를 10구단에 배치했습니다. 실제 구단 특징에서 산출한 효과가 아닙니다.
- 유형: 같은 유형 선발 3명부터 구단과 무관하게 전체 타선에 적용합니다. 출루형은 볼넷 +4%p, 교타형은 직전 출루 시 단타 +6%p, 거포형은 주자 있을 때 홈런 +4%p, 주루형은 단타 +3%p 및 단타 때 기존 주자 20% 확률 추가 1루 진루입니다.
- 개인·타순: 앞 타자 출루, 베이스 상황, 2아웃, 마지막 이닝, 7~9번 배치 등으로 발동합니다. 직전 타자 지원은 한 타석만 지속하고 이닝 종료 시 초기화됩니다.

벤치는 어떤 인원수 시너지에도 포함하지 않습니다. 주루형 추가 진루와 고유 주루 능력은 중복해서 2루씩 더하지 않습니다. 기본 규칙은 안타 종류만큼 일괄 진루이며 도루 시스템·병살·희생타·투수·수비는 구현하지 않았습니다.

## 영입과 시간

- 시작: 응원 구단에서 무작위 3명, 서로 다른 6개 다른 구단에서 각각 1명.
- 후보: 미보유 응원 구단 1명, 미보유 타 구단 1명, 현재 가장 많은 타격 유형 우선 1명을 고른 뒤 섞습니다. 중복 후보·보유 선수는 제외합니다. 해당 풀 소진 시 다른 선수로 채웁니다.
- 새로고침: **판 전체 2회**. 가능한 범위에서 직전 후보를 제외하며, 응원 구단·타 구단 보장을 유지합니다. 영입 건너뛰기는 횟수를 쓰지 않습니다.
- 8라운드 × 3이닝, 목표 1/2/4/6/8/10/12/15점, 이닝 상한 30타석. 시작 영입 포함 총 8회 영입, 라운드 사이 보상 7회입니다. 남은 미보유 구단 효과가 3개보다 적으면 남은 후보만 표시합니다.
- 기본 간격 3초, 2/4배속·건너뛰기 지원. 자동 시뮬레이션에서 완주 공격 연출 약 284~330초, 영입·편성 예상 200~270초를 더해 약 8~10분을 목표로 합니다. 실패·배속 사용 시 더 짧으며, 인간 플레이테스트로 확정한 시간은 아닙니다.

## 검증과 남은 조정

`node --test`: 원기록 일관성, 150명 구성, 300개 시작 타선, 후보 보정/새로고침, 구단 3/5/7명 단계, 혼합 유형, 고유 능력, 주자 이동, 합계 100%, 스테이지 종료 등 20개 테스트.

`node scripts/simulate.mjs`: 10구단 × 2개 단순 영입 전략 × 300판 = 6,000판. 현재 단일 구단 우선 전략 클리어율 36~71.3%, 기본 출루 확률 우선 혼합 전략 29~46.3%. 두 전략 모두 완주할 수 있으나 구단 간 격차와 혼합 전략의 개선 여지가 있습니다. 혼합 전략은 타순 최적화나 능력 연쇄를 탐색하지 않는 단순 기준이므로 이를 최적 덱 비교나 밸런스 확정의 근거로 사용하지 않습니다.

선수 150명은 확보했지만 **첫 공개판 밸런스 완료**를 뜻하지 않습니다. 10분 체감 시간, 초반 탈락률, 구단 간 편차, 혼합 덱 다양성을 지인 테스트에서 검증해야 합니다. 로고·사진 대신 텍스트와 CSS 그래픽만 사용합니다.


## 초반 적응 난이도

1라운드 목표는 1점, 2라운드는 2점입니다. 전체 타자에게 단타 확률 +20/+18%p를 적용하며 3라운드부터 이 보너스는 사라집니다. 보너스는 아웃 확률에서 이동하고 편성 안내·경기 적용 확률·중계에 표시합니다. 강제 승리나 결과 재추첨은 하지 않습니다.

추가 영입·구단 효과·타순 변경 없는 시작 타선으로 구단별 2,000판씩 확인했습니다. 라운드별 독립 통과율은 1라운드 99.85~100%, 2라운드 99.25~99.85%였습니다. 첫 라운드 실패 시에도 두 번째 라운드를 별도 측정하므로 두 라운드 연속 통과율은 아닙니다. 재현 명령은 node scripts/check-opening.mjs입니다. 테스트는 모든 구단의 두 라운드 통과율이 각각 95% 이상인지 검사합니다.
