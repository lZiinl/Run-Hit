# RUN & HIT · 9회말 덱 (KBO 2025)

2025 KBO 정규시즌 공식 기록에 기반한 10구단·타자 150명 덱 빌딩 웹게임입니다. 첫 공개판 목표인 구단별 15명은 확보했으며, 현재는 밸런스 테스트 버전입니다. 가상 팀 4개·24명 구성은 폐기했습니다.

**게임 접속 주소:** [RUN & HIT 플레이하기](https://lziinl.github.io/Run-Hit/)

GitHub Pages 최초 설정 및 배포가 성공한 뒤 위 주소로 접속할 수 있습니다.

## 실행 및 검증

Node.js 24에서 추가 패키지 설치 없이 실행합니다.

```sh
node server.mjs
```

로컬 개발 중에는 [http://127.0.0.1:4173](http://127.0.0.1:4173)에 접속합니다. 이 주소는 실행 중인 내 컴퓨터에서만 사용하며, 지인에게는 상단의 GitHub Pages 주소를 공유합니다. `npm start`도 동일합니다.

```sh
node scripts/import-kbo.mjs --check
node --test
node scripts/simulate.mjs
node build.mjs
```

빌드 결과는 `dist/`. 원본 기록 스냅샷과 개발 스크립트는 웹 배포에 포함하지 않습니다.

배포 빌드는 JS·CSS와 모든 하위 모듈을 `assets/<내용 해시>/`에 함께 넣습니다. 파일 내용이 바뀌면 주소도 바뀌어 이전 배포의 브라우저 캐시와 섞이지 않습니다. `version.json`에는 빌드 버전과 Actions 커밋 SHA를 기록합니다. 이미 열려 있던 게임 탭은 업데이트 후 새로고침해야 합니다.

## 구현

- 응원 구단 선택 → 해당 구단 3명 + 타 구단 6명의 기본 타선.
- 영입 후보 3명: 후보별 응원 구단 30%, 타 구단 70%. 응원 구단 등장 보장 없이 중복·보유 선수를 제외합니다.
- 판 전체 후보 새로고침 2회, 영입 건너뛰기, 선발 9명·벤치 5명, 타순·선발 교체, 확인 후 벤치 선수 방출. 선발은 벤치와 교체한 뒤 방출합니다.
- 구단 3/5/7명 시너지 + 출루/교타/거포/주루 유형 시너지 + 조건부 개인 능력.
- 기록별 서로 다른 기본 확률, 공통 능력 6종·고유 능력 4종, 구단 보상 8종.
- 카드별 기준 시즌·원기록·공식 링크·기본 게임 확률·창작 효과 구분 표시.
- 8라운드, 각 3이닝, 자동 공격·일시정지·1/2/4배속·건너뛰기, 결과 복사.
- 8라운드 규칙용 로컬 최고 기록. 과거 5라운드·가상 선수 버전 기록과 분리합니다.
- 공식 이미지·로고 대신 구단명과 자체 CSS/SVG 그래픽 사용.
- 전광판형 경기 화면, 타격 결과 대형 표시, 공 궤적, 베이스 주자 표시, 홈런·만루홈런 및 득점 연출.
- 실제 득점/보너스 분리, 직전 타자와 다음 타자 구분, 적용 효과 배지, 펼쳐보는 경기 중계.
- 연출 속도는 배속에 맞춰 조정하고, 건너뛰기는 연출 없이 즉시 결과를 표시합니다. 동작 줄이기 설정을 지원합니다.

## 파일 구조와 데이터 정책

- `data/teams.js`: 기준 시즌 구단 데이터.
- `data/roster-2025.js`: 공식 기록에서 생성한 150명 원기록.
- `data/sources/`: 2025 정규시즌 원본 표와 출처·필터·해시 매니페스트.
- `rules.js`: 확률 변환식, 유형 분류, 창작 능력, 구단 시너지 및 수치.
- `data.js`: 데이터와 게임 규칙 연결.
- `engine.js`: 영입, 타격·주자 이동·시너지·스테이지 판정.
- `app.js`, `style.css`: 화면과 입력, 자동 진행, 로컬 기록.

선정 기준은 각 구단의 **2025 정규시즌 타석 상위 15명**입니다. 이적 선수는 KBO 시즌 표의 구단 귀속과 해당 시즌 합계 기록을 따릅니다. 다른 시즌 수치는 섞지 않습니다.

정확한 변환식, 분류 기준, 출처, 갱신 방법과 시뮬레이션 결과는 [데이터·규칙 문서](docs/DATA_AND_RULES.md)에 있습니다.

## GitHub Pages

연결된 저장소: [lZiinl/Run-Hit](https://github.com/lZiinl/Run-Hit)

현재 로컬 브랜치는 `master`이며 워크플로는 `master`와 `main` push 모두 지원합니다. 원본 대조 → 테스트 → 정적 빌드 → Pages 배포 순서입니다.

1. [저장소 Pages 설정](https://github.com/lZiinl/Run-Hit/settings/pages)을 엽니다.
2. **Build and deployment → Source → GitHub Actions**를 선택합니다. 최초 1회 필요한 저장소 설정입니다.
3. [Actions](https://github.com/lZiinl/Run-Hit/actions)에서 실패한 실행을 열어 **Re-run all jobs**를 누르거나, **Deploy game to GitHub Pages → Run workflow**를 실행합니다. 이후 직접 커밋·push하면 자동 배포됩니다.
4. 성공한 배포의 URL을 지인에게 공유합니다.

공유 주소는 [https://lziinl.github.io/Run-Hit/](https://lziinl.github.io/Run-Hit/)입니다. 저장소 경로 `Run-Hit`의 대소문자를 유지합니다. 실제 배포 성공 여부는 Actions에서 확인해야 합니다. 링크는 공개 접속용이며 지인 전용 접근 제어는 없습니다.

### `Get Pages site failed` / `Not Found` 오류

2026-10-31 첫 실행에서는 원본 대조, 테스트 16개, 빌드가 모두 통과했지만 `actions/configure-pages@v5`에서 Pages 사이트를 찾지 못해 중단됐습니다. 위의 Pages 설정에서 Source를 **GitHub Actions**로 지정한 뒤 다시 실행하세요. 이 오류 해결에는 게임 코드 수정이나 새 커밋이 필요하지 않습니다.

## 검증 상태와 단순화

원기록 두 표 대조 및 자동 테스트 25개를 통과했습니다. 6,000판 단순 전략 시뮬레이션에서 구단 중심·혼합 덱 모두 완주하지만 승률 격차가 남아 있으므로 구단 효과는 임시값입니다.

목표 점수는 1/2/4/6/8/10/12/15점입니다. 1~2라운드에만 단타 확률 +20/+18%p 적응 보너스를 적용합니다. 추가 영입 없는 구단별 2,000판 시뮬레이션에서 1라운드 99.85~100%, 2라운드 99.25~99.85% 통과를 확인했습니다. `node scripts/check-opening.mjs`로 재현할 수 있습니다. 완주 공격 연출은 기본 타석 간격 3초에서 약 289~325초, 선택·편성 시간 포함 약 10분을 목표로 합니다. 실패나 배속·건너뛰기는 더 짧으며 실제 지인 플레이테스트가 필요합니다.

볼넷·사구는 같은 결과로 묶고, 희생타·기타 잔여 타석은 아웃 범주로 단순화합니다. 안타는 정해진 칸만큼 일괄 진루하며 투수·수비·도루·병살은 없습니다. 벤치가 가득 찼을 때 영입 교체된 기존 선발은 방출됩니다.

로그인·공용 랭킹·기기 간 동기화·진행 중 저장은 없습니다. 새로고침하면 현재 판은 사라지고 최고 기록만 남습니다. 폰트 연결 실패 시 시스템 글꼴로 표시합니다.

이번 경기 연출 변경은 자동 테스트·빌드까지 확인했습니다. 미리보기 서버 실행이 승인되지 않아 실제 브라우저 레이아웃과 애니메이션 검증은 남아 있습니다.
